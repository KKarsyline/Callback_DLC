# 最后一次证据核对与后台刷新

选出候选后，聊天宿主保留原选择令牌，在把上下文交给回复模型前调用一次 `final_admission`。它复用 `assoc_validate(recheck_only=True)` 核对当前原文、版本、作用域、令牌和有效期，返回新读到的计划与后续。此步不调用语言模型，不增加一次选择记录。来源已撤回、额度外超时或对端还不支持协议时，只保留原有直接回复；额外等待与候选选择共享同一份预算。已经送进模型的文字无法追溯撤回。

计划复核现在同时给抽取器和复核器看有效计划与后续引文附近的窗口，分段保留出处。模型漏项、字段不完整时，已有有效状态保留，未完成的复核允许重试；来源确实作废或关系失效时，原结果仍失去资格。常规刷新不会仅因安装新版而批量重算旧条目。旧版已写成未知的条目没有可靠的错误原因标记，有历史证据时可显式对一个线索调用 `refresh_plan_states(index, limit=1, repair_unknown_ids={cue_id})`。不要把所有未知结果当成损坏记录。用户只留过计划时，模型仍只看见计划引文。

OB 适配器区分有效的空授权和无法读取的策略。前者排除相应条目；后者让本次读取不可用，并中止依赖完整清单的清理，保留先前的派生数据供恢复后重新核对。

运行 `python -m pytest -q` 可复跑三个回归组。此次补丁未处理其它独立的分支继承、提及判定、跨时区排序等事项。
